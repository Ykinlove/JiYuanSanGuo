---

## 1. 设计目标

M3 解决了"战前怎么摆"，M4 要解决**"摆完之后仗怎么打"**。

三个必须做到的事：

| 目标 | 反例（如果不做会怎样） |
| --- | --- |
| **布阵加成要真实影响战斗** | M3 算出的战力只是界面上的数字，进战场后敌人还是一根抽象血条 |
| **兵种克制要玩家能感知** | 克制只写在文档里，实战中看不出差异，玩家就不会去研究配兵 |
| **战斗要有戏剧性时刻** | 部队都是安静地打到兵力归零，没有"兵败如山倒"的溃散，战场平淡 |

---

## 2. 架构

```
BattleScene（输入输出 / HUD / 结算）
    │
    └─ BattleDirector（总指挥：布置部队 / 驱动 tick / 判胜负）
            │
            └─ BattleUnit × N（单支部队：状态机 / 索敌 / 攻防 / 士气）
```

**关键设计：战斗逻辑与渲染解耦。** `BattleDirector` 只操作坐标和数值，不关心怎么画；
`BattleUnit` 自己负责程序化绘制（六边形 + 血条 + 状态标签）。
贴图就绪后只需替换 `_build_visual()`，战斗逻辑一行不用改。

## 3. 双轨生命值：兵力 + 血量

每支部队有**两套生命值**，任一归零即阵亡：

| 轨道 | 含义 | 受击变化 |
| --- | --- | --- |
| `hp` 血量 | 部队的"承受力"，由兵种决定 | `− 伤害值` |
| `count` 兵力 | 部队的人数，直接影响输出 | `− ceil(伤害 × 0.55)` |

**为什么要双轨？**

- 只有血量 → "象兵 hp320" 和 "弓箭手 hp70" 只是数字差，玩家感受不到"人多"
- 只有兵力 → 无法表达"精锐部队更耐打"
- **双轨之后**：象兵（hp320/count200）是"人肉城墙"，弓箭手（hp70/count120）是"脆皮输出"，
  两者在战场上的生存曲线完全不同——这才是兵种性格

**兵力影响输出的机制**（`兵力系数`）：

```
兵力系数 = clamp(残兵 / max(30, 初始兵力) × 0.7 + 0.3, 0.3, 1.0)
```

兵力满员 → 1.0，兵力剩三成 → 约 0.51，兵力见底 → 0.3。
**这意味着"打残"比"打死"更有战术价值**——一支残兵部队输出会暴跌，可以先放着不管。

## 4. 士气与溃散

### 4.1 为什么士气系统必须有真实体感

初版实现的教训（本项目真实踩过的坑）：

> 士气衰减公式最初写成 `伤害 × 0.12 × 1.6 × 0.1`，
> 实际衰减只有 `伤害 × 0.0192`——打 28 点伤害只掉 0.54 士气。
> 结果：**所有部队都是被打死，没有一次溃散**，
> 「固守 +35% 防御」「主角大招 +15 士气」这些设计全部失去意义。

**根因**：士气衰减必须按"压力累积"建模，而不是按绝对伤害。

### 4.2 三源压力模型（最终方案）

```
士气衰减 = (伤害压力 + 兵力压力 + 持续压力) × morale_decay_per_loss × 0.5

伤害压力 = (本次伤害 / 最大血量) × 100 × 0.45
兵力压力 = (1 − 残兵比) × 100 × 0.22
持续压力 = 3.2（每次受击固定）
```

| 来源 | 作用 | 为什么需要 |
| --- | --- | --- |
| 伤害压力 | 被强敌打 → 军心散 | 表达"打不过" |
| 兵力压力 | 人越少越慌 | 表达"快死光了"，且让残兵更易崩 |
| 持续压力 | 每次挨打都扣一点 | **防止僵持局**：两支高防部队互殴时，士气仍会缓慢下滑，战斗不会无限持续 |

### 4.3 溃散判定先于阵亡判定

```
if 士气 ≤ 18:  → 溃散（退出战场，残兵不计入阵亡）
elif hp ≤ 0 或 兵力 ≤ 0:  → 阵亡
```

**顺序很重要**：这就是"兵败如山倒"——人还在，但仗已经不想打了。

溃散部队向本方后方逃跑（速度 ×1.35），跑出战场边缘即移除。

### 4.4 实装验证结论

| 兵种 | 结果 | 说明 |
| --- | --- | --- |
| 藤甲兵（hp130 / def45） | 第 8 次受击后**溃散，残兵 88/160** | 能扛 → 先崩溃，撤退时还带走了 55% 兵力 |
| 弓箭手（hp70 / def6） | 第 3 次受击后**战死** | 脆皮 → 来不及崩溃就没了 |

**这条对照让"能不能扛"变成了真实的战术变量**：

- 上**重甲**拖住敌军 → 敌军会先溃散，我军保留兵力
- 上**轻甲**输出 → 换血快，但一旦被针对就成片阵亡
- 玩家可以据此设计"重甲顶前、弓兵在后"的配兵思路

## 5. 兵种克制矩阵

### 5.1 倍率规格

`1.25` = 克制 / `0.80` = 被克 / `1.0` = 中性

完整矩阵见 `combat.json` → `counter_matrix`，共 14 个兵种。
设计上遵循一条主循环 + 两条支线：

```
刀盾兵 ← 长枪兵 ← 轻骑兵 ← 刀盾兵      （基础三角：步 → 骑 → 枪 → 步）
弓兵   ← 轻骑兵                          （骑兵切后排）
长枪兵 ← 弓兵                            （枪兵怕远程）
```

**特殊兵种的克制锚点**：

| 兵种 | 特色 | 被谁克 |
| --- | --- | --- |
| 象兵 | 克步兵、弓兵，血量全游戏最高 320 | 长枪兵、龙枪兵（象征"枪阵破象"） |
| 藤甲兵 | 防御全游戏最高 45 | 大戟士 ×0.85（破甲意味） |
| 虎豹骑 / 白马义从 / 羌弓骑兵 | 精英骑兵，三维全面高于普通骑兵 | 长枪兵（精英也怕枪阵） |
| 水军 | 攻高防高，水域特化 | 弓兵（"射住阵脚"） |

### 5.2 AI 如何选择克制目标

索敌评分公式（每次 tick 重新评估）：

```
目标评分 = 距离分 × 1.2
         + 克制分 × 0.55
         + 残血分 × 0.45
         + 兵种偏好分 × 0.3

距离分     = clamp(1 − 距离 / 1600, 0, 1)
克制分     = (克制倍率 − 1.0) / 0.25        # 1.25 → +1.0，0.80 → −0.8
残血分     = 1 − 敌方血量比
兵种偏好分 = target_priority[敌方类别] − 1.0
```

`target_priority`（`combat.json`）：弓兵 1.35、步兵 1.1、骑兵/水军 1.0、
精英 0.95、特殊 0.9、象兵 0.85。

**读出来的 AI 性格**：
- 会**优先切弓兵**（1.35 权重）——因为弓兵输出高又脆
- 会**顺手收残血**（0.45 权重）——不会傻乎乎一直打满血前排
- 会**主动找自己克制的目标**（0.55 权重）——枪兵会绕过弓兵去找骑兵
- 象兵/精英被排到最后打——AI 知道"啃硬骨头要挑时机"

### 5.3 实装验证

长枪兵打轻骑兵 **21.4** 伤害 vs 打弓箭手 **14.2** 伤害，**比值 1.51**。

> 克制不是文档里的表格，而是玩家在战场上能明确感知的差异。

## 6. 伤害公式（完整）

```
单次伤害 = 攻击力
         × 兵力系数                              # 0.3 ~ 1.0
         × (1 + 布阵加成 + 冲锋加成 + 固守惩罚)
         × 克制倍率                              # 0.80 ~ 1.25
         × 基础系数（0.085）
         × 10
         × 防御减伤                              # 0.35 ~ 1.0
         × (1 ± 随机浮动 25%)
末值 = max(1.0, 结果)                            # 最小伤害保底
```

### 各因子一览

| 因子 | 取值 | 来源 |
| --- | --- | --- |
| 布阵加成 | M3 算出的阵型/阵位/行协同加权值 | `GameState.formation_slots` |
| 冲锋加成 | **+55%**（持续 2.2 秒，移速 ×1.6） | 全军突击指令 |
| 固守惩罚 | 攻方固守 **−20%** | 固守指令 |
| 固守减伤 | 守方固守受击 **−35%** | 固守指令 |
| 防御减伤 | `clamp(1 − 防御 × 加成 / 120, 0.35, 1.0)` | 兵种 + 布阵 |
| 随机浮动 | **±25%** | 让每场战斗有差异 |

**为什么保留 ±25% 随机？**
如果伤害完全确定，玩家算一次战力就知道结果，战斗变成"看数字动画"。
25% 的浮动让"以弱胜强"成为可能，也让每场仗打起来不一样。

**为什么设 1.0 最小伤害？**
防止高防对高攻时算出 0 伤害，导致双方互殴到天荒地老。

## 7. 固定步长 tick

```
每帧累加 delta，每满 0.25 秒执行一次 _simulate()
```

**为什么不用帧 delta？**

- 高端机 120fps、低端机 30fps，如果用帧 delta，高帧率设备的部队会
  **攻击频率更高**（同样的"攻击间隔"逻辑会产生漂移）
- 固定步长保证**同样的配置在任何设备上打出同样的结果**——这对单机游戏的公平性很重要
- 也与 M3 的战力预估（胜率计算）保持一致

## 8. 部队指令

| 指令 | 效果 | 设计意图 | 实测 |
| --- | --- | --- | --- |
| **全军突击** | 所有存活部队：输出 ×1.55、移速 ×1.6、持续 2.2 秒 | 打破僵局、抢占先手 | 对战局有明确推进感 |
| **固守** | 全军转防御姿态，士气 +12，攻 −20%、受击 −35% | 拖住强敌，等援军/等士气回升 | 能有效扛住一波冲锋 |
| **分队进攻** | 指定部队集中攻击最弱的敌人 | 集火收人头，避免伤害分散 | — |
| **撤退** | 强制结束战斗，按失败结算 | 保全兵力（扣减 25%~100%，保底每队 10 兵） | — |

**固守的双重效果**是精心设计的：
攻 −20% 是代价，受击 −35% 是收益，**净收益为正**——所以"龟缩流"是可行的，
但输出下降意味着时间拖长，敌方士气会自然恢复（脱战恢复），不能无限龟。

## 9. 主角参战

| 操作 | 条件 | 效果 |
| --- | --- | --- |
| 普攻 | 最近敌军 **≤ 260px** | 伤害 14–24 ×(1+布阵攻击加成) |
| 大招 | 怒气 ≥ 50 | 打击最靠前 2 支部队（第二支 ×0.6）+ **全军士气 +15** |
| 闪避 | — | 0.6 秒无敌帧 |

**普攻的距离门槛**是很重要的手感设计：
如果主角能隔半屏攻击，玩家就会站在原地刷，战场变成"主角一个人打"。
限制 260px 意味着**玩家必须走进战场**，才会真正感受到"被包围"的压力。

**大招的双重价值**（伤害 + 士气）让主角成为**战场的士气锚点**：
实测中，主角大招把 3v3 战斗从 **48 tick 压缩到 36 tick**，
同时友军士气大幅提升——主角不是"一个高攻单位"，而是能扭转军心的存在。

## 10. 战场可读性

**这可能是 M4 最重要的一条设计原则**：AI 打得再聪明，玩家看不懂就是白做。

| 机制 | 目的 |
| --- | --- |
| **战场日志**（左下角，滚动 4 条） | "长枪兵 克制 轻骑兵""敌军 弓箭手 溃散！"——让玩家看见 AI 的决策 |
| **部队状态标签** | 部队头顶显示「冲 锋」「溃 散」，一眼看清战场态势 |
| **士气数字** | 士气 < 45 时显示"气 78"，让溃散有预警（不是突然消失） |
| **血条三色** | >55% 绿 / 25–55% 黄 / <25% 红，残血部队一眼可辨 |
| **HUD 战况条** | "我军 3 队 / 420 兵　　敌军 2 队 / 180 兵"，实时掌握兵力对比 |
| **部队体积随兵力变化** | `半径 = 26 + clamp(兵力/12, 0, 20)`——人多看起来就是一大团 |

**设计取舍**：我们**没有**做"敌方部队血条统一显示在顶部"。
每支部队有自己的血条，虽然更占屏幕，但玩家能清楚地看到
"打哪支更划算"——这是把决策权交给玩家。

| --- | --- | --- |

## 12. 开发约束

给后续开发的硬性约束：

1. **战斗逻辑不得依赖渲染**——`BattleDirector` 与 `BattleUnit` 不引用任何 UI 节点，
   HUD 通过 `situation()` 拉取数据。这样战斗可以被无头测试。
2. **所有数值必须来自 `combat.json`**——禁止在脚本里硬编码伤害系数、士气阈值。
   调平衡只改 JSON，不改代码。
3. **固定步长不可改为帧 delta**——否则不同机型结果不一致。
4. **部队视觉可替换**——`_build_visual()` 是唯一的绘制入口，贴图就绪后替换此函数即可。
5. **`_verify_combat.py` 必须随数值改动同步更新**——它是独立的 Python 复算，
   与 GDScript 实现互不依赖，用于交叉验证公式正确性。
