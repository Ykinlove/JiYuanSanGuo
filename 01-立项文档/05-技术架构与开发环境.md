## 1. 技术选型结论

| 项目 | 选型 | 理由 |
| --- | --- | --- |
| 引擎 | **Godot 4.x**（稳定版） | 免费开源无抽成、2D 强、导出安卓极简、包体小 |
| 脚本语言 | **GDScript** | 与引擎深度集成，开发快；C# 为备选 |
| 渲染器 | **Compatibility（OpenGL ES 3.0）** | 覆盖低端机，2D 游戏最佳选择 |
| 版本控制 | Git + GitHub/Gitee | 代码与资源版本管理 |
| 美术工具 | 见《美术资源》章节 | AI 生成 + 后期修整 |
| 音频工具 | Audacity / FL Studio / 免费音效库 | — |

### 1.1 为什么选 Godot 而不是 Unity / Cocos

| 引擎 | 结论 |
| --- | --- |
| **Godot 4.x** ✅ | 2D 能力优秀、完全免费商用、导出安卓简单、工程小、适合独立团队 |
| Unity 6 | 生态最强但包体大、个人版营收条款需注意、2D 项目略重 |
| Cocos Creator | 若将来一定要发**微信小游戏**则更优，但重度 RPG 后期吃力 |
| 单HTML+Capacitor | 迁移性最强但性能天花板低，不适合本类游戏 |

> **迁移性说明**：Godot 工程主体可直接导出 Android / Windows / Linux / Web(HTML5)。
> 微信小游戏需第三方转换工具链（如 Godot 转微信小游戏方案），非官方原生支持，
> 若后期确需小程序版本，届时评估专用方案。

## 2. 需要你下载安装的软件

### 2.1 必装（基础开发环境）

| # | 软件 | 用途 | 下载地址 | 备注 |
| --- | --- | --- | --- | --- |
| 1 | **Godot 4.x（.NET 或 标准版）** | 游戏引擎 | godotengine.org/download | 选 **Standard 标准版**（用 GDScript 无需 .NET） |
| 2 | **Android Studio** | 提供 Android SDK | developer.android.com/studio | 只需用它装 SDK，不必用其写代码 |
| 3 | **JDK 17** | Android 构建依赖 | adoptium.net（Temurin 17 LTS） | **版本敏感**，务必用 17 |
| 4 | **Git** | 版本控制 | git-scm.com | — |

### 2.2 推荐（效率提升）

| # | 软件 | 用途 |
| --- | --- | --- |
| 5 | **VS Code** | 写 GDScript（配 Godot 插件）或写文档 |
| 6 | **Krita / GIMP** | 免费图像编辑，修整 AI 生成图、抠图、切图 |
| 7 | **Aseprite** | 像素/序列帧动画（如需帧动画） |
| 8 | **Audacity** | 音频剪辑 |
| 9 | **Everything** | 文件极速搜索（你本地文件多时很实用） |

### 2.3 Godot 导出 Android 的关键配置（重要）

安装完上述软件后，需要在 Godot 中配置：

1. **编辑器设置 → 导出 → Android**
   - 设置 **Android SDK 路径**（Android Studio 安装目录下的 SDK）
   - 设置 **JDK 路径**（JDK 17 安装目录）
   - 生成/指定**调试密钥库**（debug keystore，Godot 可自动生成）

2. **项目 → 导出 → 添加 Android 预设**
   - 包标识符：`com.yourstudio.epochsg`（需唯一）
   - 架构：勾选 **arm64-v8a**（覆盖绝大多数现代安卓机）
   - 渲染器：**Compatibility**
   - 安装 **Android 构建模板**（点击按钮，会复制 Gradle 项目到 `android/build`）

3. **发布前**
   - 生成 **release keystore**（自建，务必备份！丢失则永远无法更新同一应用）
   - 开启 **Use Gradle Build**
   - 若需外置资源包，开启"允许用户数据写入外部存储"

### 2.4 移动端性能优化清单

| 优化项 | 做法 |
| --- | --- |
| 渲染器 | Compatibility（2D 最佳） |
| 纹理压缩 | 项目设置 → 渲染 → 纹理 → VRAM Compression → 开启 **ETC2/ASTC**，**然后必须重新导入资源** |
| 纹理尺寸 | 尽量 2 的幂，单边 ≤ 2048 |
| Draw Call | 使用 **TextureAtlas 纹理图集**合并精灵 |
| 帧率 | `Engine.max_fps = 60`（或 30 省电） |
| 特效 | **Compatibility 下 GPUParticles 无效**，用 **CPUParticles2D** |
| 粒子预算 | ⚠️ **CPUParticles2D CPU 开销高于 GPU 粒子**：战场必须限制同屏粒子最大数量（建议单特效 ≤ 30 个粒子、同屏特效 ≤ 8 组），避免百人战场在低端机上严重掉帧；特效需做层级裁剪（远景关闭粒子） |
| 真机测试 | 必须真机 profile，编辑器性能不代表手机 |

## 3. Godot 项目架构设计

```

│       └── events.json

│   ├── world/
│   ├── battle/
│   ├── characters/
│   └── systems/
└── android/                     # 导出时生成
```

### 3.2 核心自动加载单例（Autoload）

| 单例 | 职责 |
| --- | --- |
| `GameState` | 当前存档的游戏数据（角色、部队、城池、势力关系、时间） |
| `SaveManager` | 存/读档，多存档槽，自动存档 |
| `DataManager` | 加载 JSON 静态数据表，提供查询接口 |
| `AudioManager` | BGM/SFX 播放与音量管理 |
| `SceneRouter` | 场景切换 + 过渡动效（渐隐） |
| `EventBus` | 全局信号总线（解耦模块通信） |

### 3.3 数据驱动设计（重要）

**所有游戏内容用 JSON 数据表驱动**，不写死在代码里：

```json
// characters.json 示例
{
  "id": "guan_yu",
  "name": "关羽",
  "style_name": "云长",
  "stats": { "constitution": 95, "strength": 97, "intelligence": 75, "charisma": 88 },
  "skills": ["green_dragon_slash", "loyalty_aura"],
  "talent": "warrior_saint",
  "unit_aptitude": { "cavalry": "S", "infantry": "A" },
  "biography": "字云长，河东解良人……",
  "portrait": "res://assets/sprites/characters/guan_yu.png"
}
```

**好处**：
- 策划改数值不用碰代码
- 方便批量配置武将、城池、道具
- 未来可支持 MOD

## 4. 手机UI适配方案

### 4.1 分辨率策略

- 设计基准分辨率：**1920 × 1080**（横屏 16:9）
- 使用 Godot 的 **CanvasItems + stretch mode = `canvas_items`** + `aspect = expand`
- UI 全部使用 **锚点（Anchor）+ 容器（Container）** 自动适配
- 安全区域：处理刘海屏/挖孔屏（`DisplayServer.get_display_safe_area()`）
- **横屏锁定**：`project.godot` 中 `display/window/handheld/orientation = 1`（Landscape）

### 4.2 触控UI规范

| 控件 | 规范 |
| --- | --- |
| 虚拟摇杆 | 最大半径 80px，死区 10px，跟随手指出现 |
| 按钮 | 最小点击区 **48×48 dp**（约 96×96 px @2x） |
| 按钮间距 | ≥ 16 dp，防误触 |
| 手指遮挡 | 关键信息避开屏幕下 1/3 与右上角 |
| 反馈 | 按下缩放 + 音效 + 轻微震动 |

### 4.3 布局示意（横屏 1920×1080）

```
┌──────────────────────────────────────────────────┐
│ 顶部状态栏：金钱 / 粮草 / 木材 / 兵力  ·  日期     │
├──────────────────────────────────────────────────┤
│                                                  │
│                                                  │
│                 游戏主视图区                      │
│            （大地图 / 战斗 / 城池）               │
│                                                  │
│                                                  │
├──────────────────────────────────────────────────┤
│ ○摇杆   △ □ 部队指令        ◇技能 ◇大招 ⬤攻击 ✕闪避│
└──────────────────────────────────────────────────┘
```

## 5. 存档方案

| 项目 | 方案 |
| --- | --- |
| 存档格式 | JSON（可读、易调试）或 Godot `Resource` 二进制 |
| 存档位置 | `user://saves/slot_N.json` |
| 存档数量 | 5–10 个手动槽 + 1 个自动槽 |
| 存档内容 | 角色、部队、武将、城池、势力关系、任务进度、世界时间、地图标记 |
| 云存档 | 待确认（需联网，可用最简单方案：导出/导入存档文件） |

> **存档安全备注**：
> - **Demo 阶段**：直接使用明文 JSON，方便调试与手工修改验证。
> - **正式发布版本**：增加简单 **CRC 校验**，阻止普通玩家手动修改存档文件；不做高强度反篡改（本项目为免费单机，无内购，篡改无直接收益，仅需防止误改导致存档损坏）。

## 6. 开发里程碑（建议）

| 里程碑 | 内容 | 产出 |
| --- | --- | --- |
| M0 | 环境搭建 | Godot + Android SDK 配好，能导出空 APK 到手机 |
| M1 | 核心框架 | 场景切换、存档、数据表加载、UI 框架 |
| M2 | 大地图行走 | 主角可控 + 地图碰撞 + 遭遇触发 |
| M3 | 战斗原型 | 即时战场 + 主角操作 + 部队指挥 |
| M4 | 城镇与 NPC | 进城、对话、任务、商店 |
| M5 | 招募与征兵 | 武将入队、士兵管理 |
| M6 | **Demo 定版** | 打通完整中循环，出可玩版本 |
| M7+ | 内容补齐 | 剧情、关卡、势力线、优化 |

> **Demo 完成后迭代原则**：优先收集**战斗手感反馈**，集中调优打击感、兵种平衡、部队 AI 响应；手感达标后再扩充剧情、地图、势力内容。避免剧情做完才发现核心战斗不好玩。
