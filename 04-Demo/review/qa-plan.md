## 一、体验断点清单（沿新玩家前 30 分钟动线）

### B12（P0）主线任务达成后无任何提交入口，主线链死链

- **动线步骤**：创角落地 → intro 引导自动接 mj_hj_01 → 打 3 场黄巾 → 目标 3/3 达成 → 找地方提交
- **预期**：回"发布人"处提交 → 奖励入账 → 自动接 mj_hj_02（quest_service.gd:219-223 next 链）→ 主线推进
- **代码证据链**（四环闭合）：
  1. 提交入口唯一：`dialogue_ui.gd:405-421`——只有打开**含 `accept_quest:<qid>` 动作的对话节点**且任务进行中且目标全达成时，选项才变为「提交任务」；`dialogue_ui.gd:513` 调 `QuestService.turn_in`。全 scripts 目录 grep `turn_in`，运行时调用者仅此一处。
  2. `mj_hj_01` 接取点 = 开场收尾节点 `intro_goals`（dialogues.json），由 `intro`→`intro_guide`→`intro_goals` 链式触发、仅新档播一次（`world_map.gd` intro_seen 门控），动作含 `accept_quest:mj_hj_01`；原 `mj_ch1_guide` 孤儿节点（不可达断点）已于 2026-09-28 批次 G 清理，功能并入 `intro_goals`；`quests.json` 中 mj_hj_01/02/03 的 `giver_npc` 全部为空串。
  3. `quest_panel.gd:4` 写明"交付不在此处：回发布任务的 NPC 对话提交"，任务卡完成时提示"回去找发布人提交吧"（`quest_panel.gd:159`）——该接取断点已于 2026-09-28 批次 G 修复：`intro_goals`（开场链末端）现含 `accept_quest:mj_hj_01`，新档首进大地图播一次即可接取；原不可达的 `mj_ch1_guide` 旁白节点已删除。
  4. 断点波及面（逐一核对 dialogues.json 的 accept_quest 清单）：**mj_hj_01、mj_hj_02、mj_hj_03、ch2_01、ch2_03、ch2_04、ch3_03、ch4_02、ch4_03、ch4_04、ch6_05、ch7_03、ch7_05、ch7_06** 这 14 环无任何提交节点（其中 ch6_05 是第六章章末任务，mainline_service.gd:125-127）。每环断裂即封锁其 `next` 后继。
- **现象**：黄巾清剿 3/3 后，任务中心永久显示"目标已全部达成：回去找发布人提交吧"，玩家找不到任何可提交的 NPC；任务栏首项永不消失，后续主线全部接不到。
- **唯一绕行**：`enc_zhangjue_boss`（zhongyuan 区域随机刷新）战斗胜利直接推章（`mainline_service.gd:84-85` on_battle_win 不经 turn_in）——但依赖随机撞上，且 mj 系任务仍永久卡死。
- **验证方法**：新档跑完 intro → 打 3 场黄巾 → 遍历南中全部 NPC 对话 → 无提交选项；任务中心 3/3 卡死。
- **修复建议**（三选一，b 最小）：a) 为各断环补发布 NPC 对话节点（ch 系列含 talk 目标的任务已是此模式，如 ch1_05→han_envoy_intro）；b) `record_event` 记账后检测 `can_turn_in`，对无 giver_npc 的任务自动 turn_in + toast（reach/battle 类目标本就无需 NPC 交互背书）；c) 任务中心 ready 卡片直接给「提交」按钮。

### B3（P1）「新的征程」无覆盖确认，静默覆盖自动存档

- **动线步骤**：老玩家（已有 auto.json 进度）进主菜单 → 点「新的征程」→ 走完创角
- **预期**：提示"将覆盖当前自动存档"或双档并存
- **代码证据**：`main_menu.gd:33-35` 直接 `goto("create_hero")` 无任何确认；`create_hero.gd:866-883` `_confirm()` 里 `GameState.reset()` 后无条件 `SaveManager.auto_save()`（save_manager.gd:74-75 → 槽 0 auto.json）。手动 3 槽不受影响，但自动档（含玩家最新进度，默认读档入口）被无声覆盖。
- **现象**：误点「新的征程」并走完三步 → 上次进度只剩手动槽（若没手动存过=全丢）。
- **验证方法**：造一档进度 → 新的征程走完 → 读自动档，确认是新角色。

### B2（P2）主菜单「继续」读档失败完全静默

- **动线步骤**：存档损坏/缺失 → 主菜单点「继续」
- **预期**：提示"存档已损坏"之类
- **代码证据**：`main_menu.gd:38-42` `if SaveManager.load_game(...)` 无 else 分支；`save_manager.gd:59` 失败时 `EventBus.show_toast("存档已损坏")`；但 toast 消费方仅 world_map/city_scene/battle_scene/formation_editor 四处（grep `toast.connect`），**main_menu 未连接** → 提示发进虚空。
- **现象**：点了没反应，玩家以为按钮坏了。
- **验证方法**：手动写坏 auto.json → 点「继续」→ 无任何反馈。

### B4（P2）创角场景 toast 提示无人消费

- **动线步骤**：创角第二步 → 点「＋」超限 / 点「下一步」时点数未分完
- **代码证据**：`create_hero.gd:790,794,850` 发 toast（"点数已分配完了"/"单项最高 80"/"还有 N 点未分配"），但 create_hero 场景未 `EventBus.toast.connect`（同 B2 证据）。按钮 disabled 态（`create_hero.gd:940`）部分兜底，但"为什么点不了"的文字提示全部丢失。
- **验证方法**：创角第二步点满 10 点后再点「＋」→ 无文字提示。

### B5（P2）开场教学文案与现行交互模型不符（新玩家第一步被误导）

- **动线步骤**：首次大地图 → intro_guide 教学
- **代码证据**：dialogues.json `intro_guide` 说"靠近 NPC 时，**贴脸交互菜单会自动弹出**"、"**右上缩放按钮**可拉近拉远视野"。但 2026-09-24 已拍板改为"靠近亮提示，**点右下交互按钮**才弹菜单"（`world_map.gd:698-700` 注释、`_on_city_action` 1353-1361），缩放按钮也已移除（`world_map.gd:1271` 注释"缩放按钮已移除"）。
- **现象**：新玩家站在 NPC 旁等菜单"自动弹出"→ 等不到；找"右上缩放按钮"→ 不存在。教学的每一个字都有代码出处，但教的是旧版本。
- **验证方法**：新档听完教学，对照实际 UI 逐条核对。

### B8（P2）采集点 daily_limit 形同虚设，"今日 1/5"却不能再采

- **动线步骤**：大地图走近采集点 → 点「交互」→ 采集成功（toast"采集到 X（今日 1/5）"）→ 再点「交互」
- **预期**：当日可继续采至 5/5
- **代码证据**：`encounter_manager.gd:319` `_handle_gather` 无条件 `_triggered_ids[enc_id] = true`；`nearest_interactable`（196-198）与 `_process` 手动目标筛选（266 行）均跳过 `_triggered_ids` → 采 1 次后该点当日内从"可交互候选"中消失；`_respawn_daily`（389-397）次日才解锁。daily_limit（316 行）计数永远停在 1。
- **现象**：提示"今日 1/5"与"不能再采"自相矛盾，玩家以为是 bug（实际上它就是）。
- **验证方法**：对任一 gather 遭遇连点交互按钮两次，观察第二次无响应。

### B10（P2）删除存档无二次确认

- **代码证据**：`save_menu.gd:80-83` 删除按钮直接 `SaveManager.delete_save(slot_no)` + `_refresh()`，无确认弹窗。140×96 的大按钮，误触即永久丢档。
- **验证方法**：存档菜单点「删除」→ 立即消失，无拦截。

### B11（P2）存档菜单也是 toast 盲区：读损坏档点击无反应

- **代码证据**：`save_menu.gd:91-93` `if SaveManager.load_game(slot): push_scene("world")`；失败分支只有 save_manager 内部 toast（save_manager.gd:59），save_menu 场景未连接 toast（同 B2 证据链）。
- **现象**：列表里点了坏档 → 毫无反应，无"已损坏"提示。（与 B2 同根：**toast 机制缺少场景无关的全局消费层**，建议挂一个 autoload 级 ToastLayer，一修全修。）

### B6（P2，条件触发）交互菜单展示未实装的「赠礼」动作

- **代码证据**：`interaction_menu.json:49-54` 定义 gift；rules（103-111 行）对 tags 含 `hero` 的 NPC 出「赠 礼」选项；`world_map.gd:1013-1014` `_do_gift` → toast"送礼界面待实装"。触发条件为 NPC tags 命中 hero 规则（大地图 NPC tags 由 `npc_manager` 生成时决定，本次未逐一验证），凡命中即把"待实装"功能摆进玩家菜单。
- **建议**：未实装动作在 rules 表中先摘除，或 `interaction_menu.json` 加 `implemented:false` 由菜单渲染时置灰隐藏。

### B14（P3）boot 固定 1 秒演出不可跳过

- **代码证据**：`boot.gd:10-14` 两次 `create_timer`（0.6s + 0.4s）纯等待。每次启动白付 1 秒。建议压缩到 0.3s 或允许点击跳过。

### B15（P3）详情类信息用 toast 展示长文本，7.6 秒即逝

- **代码证据**：`world_map.gd:949-974` `_show_info` 把名称/描述/列传/四维拼成一串走 `show_toast`（1286-1296：停留 7.6s）；文字量大时读不完且无法回看。建议改用 CharacterPanel 详情面板。

### B16（P3）城内面板冻结判断 12 段复制粘贴，未收敛成表驱动

- **代码证据**：`city_scene.gd:595-651` 逐个 if 判断 12 类面板 is_open；大地图同逻辑已收敛为 `_any_ui_open()` 一张表（`world_map.gd:296-305`，注释自述"漏掉一个就会出现弹窗开着人还在跑"）。两场景模型不一致，城内下一个新面板就是下一个漏网。
- **验证方法**：结构比对两文件 `_process` 前段。

### B17（P3）SceneRouter.push_scene 无条件污染历史栈

- **代码证据**：`scene_router.gd:67-69` 先 append 再调 goto；goto 在 `_is_transitioning` 时直接 return（39-40）——被拒绝的跳转仍留在历史里，其后一次 `back()` 会退到错误场景。当前流程链验证过主路径正确（world→city→world；world→formation→battle(goto 不入栈)→back 回 world；演武 city→formation→battle→back 回 formation→back 回 city，`battle_scene.gd:900-908`），但连点窗口（渐黑前 0.3s）存在退错层的风险。
- **验证方法**：过渡动画期间快速连点「进入」两次，出城观察落点。

### B18（P3）存档写入非原子，断电/崩溃可损坏档

- **代码证据**：`save_manager.gd:32-37` 直接 `FileAccess.open(path, WRITE)` 覆盖写，无 tmp+rename，无 .bak 回退。from_dict（game_state.gd:674-757）字段宽松可兜住缺字段，但 JSON 半截写入仍是 parse 失败 → 该档报废。Demo 阶段可接受，建议加"写 tmp → 校验 → rename"与上一版 .bak。

### B19（P3）战败结算无下一步指引

- **代码证据**：`battle_scene.gd:821-825` 败北文案"部队撤退，损失部分兵力"为止；保底 25% 兵力（`_apply_defeat_penalty` 852-855）已有，但玩家不知道该去兵营补兵/施赈恢复民心。建议败北结算追加一行"前往兵营补充兵力，官府施赈可提升征兵上限"。

### 走查确认没问题的环节（免测心证）

- **引导闭环存在（2026-09-28 批次 G 已闭合）**：intro → intro_guide（操作教学+送 500 金 500 粮 5 名声）→ intro_goals（讲战斗/目标 + `accept_quest:mj_hj_01` + flag_intro），dialogues.json 三个节点由 `world_map.gd` intro_seen 门控仅新档播一次。原 `mj_ch1_guide` 孤儿节点已删除，断点消除。

## 二、Bug 分级标准（Demo 适配四级）

| 级别 | 定义 | 放行规则 | 本项目实例 |
|---|---|---|---|
| **P0** | 崩溃/软锁/核心玩法循环阻断——玩家无法继续本应可用的主流程 | 0 个方可对外 | **主线任务无提交入口，14 环死链**（B12：目标达成后全工程无 turn_in 路径，主线推不动） |
| **P1** | 功能阻断或数据丢失风险——有绕行，但玩家大概率踩中且损失真实 | 外发前必须修或有显式告警 | **「新的征程」无覆盖确认静默覆盖自动存档**（B3：auto_save 无条件覆盖槽 0） |
| **P2** | 体验缺陷——能玩，但困惑/误导/反直觉，会进玩家反馈 | 排期批量修 | **读档失败静默**（B2/B11：toast 在主菜单/存档菜单无人消费，点击无反应）；**教学文案教旧版交互**（B5） |
| **P3** | 打磨项——锦上添花，不修不影响通关 | 记录在案，版本间隙处理 | **boot 固定 1 秒不可跳过**（B14）；详情长文本 7.6 秒即逝（B15） |

判定原则：P0/P1 看的是"主流程是否还成立 + 玩家数据是否安全"，不以崩溃与否为唯一标准；Demo 阶段玩家耐心极低，"误导性引导"（B5）按 P2 上限处理。

## 四、必须真机/真人验证清单（无头探针覆盖不了）

1. **触控手感**：虚拟摇杆死区与跟手度（player_controller 输出曲线）；右下 140px 交互钮与摇杆对端拇指位是否互扰。操作：南中平原连续走位 3 分钟 + 靠近 10 个不同目标各交互一次。
2. **双事件输入**：emulate_touch_from_mouse 下选项按钮/对话推进有无"点一下当两下"。操作：intro 教学段快速连点 20 次，观察是否跳段/误选。
3. **帧率与发热**：大地图（地形 LOD + 140 遭遇节点 + NPC 群）与战斗（BattleDirector 全量部队）两场景各 15 分钟。记录：平均帧率、掉帧尖峰、机身温度、耗电。
4. **长时会话内存**：连续进城/出城/战斗 10 轮（场景重载路径），观察内存是否阶梯上涨（queue_free 泄漏探针测不到的纹理缓存类泄漏）。
5. **分辨率与安全区**：至少 16:9、20:9、21:9 三档真机 + 平板 4:3。检查：HUD 三段（资源/区域/日期）不压叠（hud.gd compact<1800 分支）、刘海两侧按钮（右上菜单钮、右下交互钮）不在切割区、对话卡不顶刘海。
6. **BGM 循环与打断**：world_map/city/battle 三段 BGM 循环处有无爆音；战斗入场 BGM 切换是否干脆。
7. **后台切换恢复**：游玩中切后台 5 分钟再回——计时器（world_clock/月度结算）是否跳变异常、音频是否恢复。
8. **长时间文案可读性**：toast 7.6s（大地图）/7.5s（城内）在户外强光下的可读性，决定是否需要长文改为面板。

## 五、玩家反馈采集（Demo 最小可行方案）

### 渠道（按成本递增取一即可）

- **最低配**：发行包内置「意见反馈」入口（设置面板加一行）→ 复制预格式化模板 + 跳转 QQ 群/问卷链接。
- **推荐**：在线问卷（腾讯问卷/金数据）+ 群文件收存档。Demo 阶段玩家量小，人工整理足够。

### Bug 报告单（固定字段，玩家照抄填空）

```
【纪元三国 Demo Bug 反馈】
1. 现象：一句话说清你看到了什么（例：任务说去提交，但找不到人）
2. 复现步骤：1)… 2)… 3)…（从主菜单开始，每步一个动作）
3. 期望：你觉得应该发生什么
4. 实际：实际发生了什么
5. 屏幕截图/录屏：（必附）
6. 存档文件：（设置里能找到存档；user://saves/ 下 auto.json / slot_1~3.json，连同一起发）
7. 设备与系统：（例：Redmi K60 / Android 14 / 屏幕比例 20:9）
8. 联系方式：（可选）
```

- 存档是定位"任务/数值/进度"类问题（如 B12）的第一证据，**模板里必须强调附存档**。
- 建议同步在设置面板显示"存档导出"按钮（复制 JSON 到剪贴板或分享），把"找存档文件"的门槛降为零。
