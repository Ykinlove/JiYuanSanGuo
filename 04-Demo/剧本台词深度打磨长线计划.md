## 二、引擎约束（写之前必须知道，否则返工）

1. **节点串联方式**：本作**没有**节点级自动 `next`。多节拍只能靠「节点末尾选项 → `next` 指向下一节点」串联，即开场链 `intro → intro_guide → intro_goals` 的范式。
2. **旁白节点的收束**：旁白节点不带选项时（`options: []`）播完即关；若需让玩家推进/转折，用「单个中文括号式选项」（如 `（继续闯荡）`、`（合上史书）`）作为节拍按钮，`next` 指向下一节拍，最后一拍 `next: ""` 收散。
3. **⚠ 不支持变量插值**：`dialogue_ui.gd` 取行文本是直接 `_full_text = str(_lines[...])`，**不做任何 `%` 替换**。
   - 因此结局旁白**无法**打印玩家的国号 / 都城 / 自身姓名。
   - 当前应对：`mainline_service.ending_summary()`（代码侧吐司）负责注入 `GameState.self_rule_name` 国号；旁白则用「不点名的写法」绕开。
   - 后续候选增强（见第五节）：给 `dialogue_ui` 加安全的 `{guohao}` / `{name}` 令牌替换。
4. **入口 id 不可改**：`world_map.gd` 与 `mainline_service.ending_node_id()` 按固定 id 拉起结局节点，打磨时**必须保留入口 id 不变**，只能在链尾追加 `_02` / `_03`。

## 三、打磨规格（每批的验收标准，硬性）

1. **体量**：单结局从「1 节点 × 3 行」扩为 **3 节拍链（回望 / 终幕 / 落款）**，每节拍 4–5 行，整条链 **≥ 400 字**（向 `intro` 的 265 字节拍密度看齐）。
2. **结构**：三拍必有清晰功能分工——
   - 第一拍**回望**：把玩家这五十年的路压缩成具体画面；
   - 第二拍**终幕**：群雄/天下如何收场，落到私人视角而非编年表；
   - 第三拍**落款**：史官视角的判断 + 一句收束（默认线固定保留原句 `——你的名字，留在了青史之间。`）。
3. **文风**：二次元国风外壳 + 三国史诗重力。禁用现代口语、网络语、打卡式短句；允许适度文言，但以现代读者无门槛为准。
4. **一致性**：不同结局之间不许复用同一句漂亮话；每条线要有自己的情绪底色（称帝=孤家寡人的重量 / 汉室=知其不可而为之 / 霸业=得意后的空 / 归隐=轻 / 默认=当事人的沉默）。
5. **零改动接线**：入口 id 不变、`options` 结构不变、不放 `action`（结局已是终局，不再发任务给奖励）。
6. **验收**：每批必须跑通——JSON 合法 + 22 项校验全 PASS + 该结局链字数提升对比 + `_git_sync.py` 提交。
