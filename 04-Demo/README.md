## 一、这是什么

《纪元三国》的 **M5 里程碑工程**。M1~M4 解决了"**怎么打**"，M5 解决的是"**打了之后**" ——
兵从哪来、将怎么招、钱粮怎么流转、城池怎么养。

一句话概括 M5：

> **让玩家为下一场战斗做准备，并且让"准备"本身变成一个值得琢磨的决策。**

### M1 已具备（底层框架）

- ✅ 全局单例体系（事件总线 / 数据管理 / 游戏状态 / 存档 / 音频 / 场景路由）
- ✅ 数据表驱动的内容系统（JSON 配置，策划可独立改数值）
- ✅ 多存档槽（存 / 读 / 删 / 自动存档）
- ✅ **横屏**手机 UI 框架（含自研虚拟摇杆，支持触屏与鼠标调试）
- ✅ 场景切换与渐隐过渡

### M2 已具备（南中探索闭环）

- ✅ **程序化地形绘制**：山林 / 水泽 / 道路 / 地形装饰，有机多边形 + 噪声生成
- ✅ **遭遇物系统**：8 类遭遇（战斗 / 采集 / 宝箱 / 商队），权重随机刷新，采集每日上限
- ✅ **NPC 与对话系统**：就近提示、六角菜单选项、属性门槛置灰、打字机文本、动作指令
- ✅ **主角控制器**：八方向移动 / 奔跑 / 行走起伏 / 相机边界限制
- ✅ **美术贴图自动检测**：贴图存在则渲染贴图，缺失则回退程序化绘制

### M3 已具备（战前布阵系统）★

- ✅ **3×5 阵位网格**：前军/中军/后军 × 5 列，共 15 个阵位，每格独立攻防加成
- ✅ **兵种 × 阵位协同**：行-兵种匹配机制，弓兵放前排会被惩罚，放后排有加成
- ✅ **实时战力预估**：每次操作立即刷新我方战力、敌方战力、胜率百分比
- ✅ **智能自动布阵**：按兵种自动摆放（步兵抗线、骑兵中军、弓兵后排）
- ✅ **布阵合法性警告**：如"弓兵置于前排，极易被冲散"实时提示
- ✅ **统兵武将加成**：武将统率影响部队战力，「中帐位」统帅加成翻倍
- ✅ **战斗实现联动**：战场按阵位实际坐标摆出我方方阵，加成作用于战斗伤害

### M4 新增（部队 AI 自动交战）★★

- ✅ **双轨生命值**：`hp 血量` + `count 兵力` 独立结算，任一归零即阵亡
  （象兵是人肉城墙，弓箭手是脆皮输出——兵种性格终于打出来了）
- ✅ **士气与溃散**：三源压力模型（伤害 / 兵力 / 持续），士气 ≤ 18 触发**溃散离场**
  （关键设计：**溃散判定先于阵亡**——兵败如山倒，人还在，但仗已经不想打了）
- ✅ **兵种克制实装**：14 个兵种完整克制矩阵，1.25 克 / 0.80 被克
  （实测枪兵打骑 21.4 vs 打弓 14.2，**1.51 倍差**，玩家能明确感知）
- ✅ **部队 AI 状态机**：IDLE → ADVANCE → ENGAGE → ROUTED/DEAD，自行推进接敌
- ✅ **索敌评分系统**：距离 ×1.2 + 克制 ×0.55 + 残血 ×0.45 + 兵种偏好 ×0.3
  （AI 会主动切后排弓兵、顺手收残血、枪兵绕开弓兵去找骑兵）
- ✅ **4 种全军指令**：全军突击（冲锋 ×1.55 / 移速 ×1.6）/ 固守（受击 −35%、士气 +12）/
  分队进攻（集火最弱敌）/ 撤退
- ✅ **固定步长 tick**：0.25 秒一步，与帧率解耦，保证不同机型打出同样结果
- ✅ **主角参战强化**：普攻需 260px 内才命中；大招打击最靠前 2 队 + **全军士气 +15**
- ✅ **战场可读性**：滚动战斗日志（克制 / 溃散 / 击杀）+ 部队状态标签 + 血条三色 + 战况条
- ✅ 新增数据表 `combat.json`（战斗参数 / 克制矩阵 / AI 权重 / 兵种速度）

### M5 新增（城池经营与招募）★★★

- ✅ **CityService 规则层**（新文件 `scripts/city/city_service.gd`，`class_name CityService`）
  —— 26 个公共方法。把「能不能做、要花多少钱、做了有什么后果」全部从 UI 剥离，
  UI 只负责显示 `r["msg"]`。**规则层可被 Python 独立复算**，这是 M5 能一次校验通过的根本原因。
- ✅ **五建筑城池界面**：酒馆 / 兵营 / 市场 / 铁匠铺 / 官府，各自打开 1180px 滑动抽屉面板
  （不再是 M2 那种"点一下弹个提示"的占位）
- ✅ **兵营**：14 兵种征兵（四重门禁：城池等级 / 兵营存在 / 区域势力特产 / 民心）+ 练兵升级
  + 任命统兵武将（同一武将不能带两支部队）
- ✅ **酒馆**：8 名武将明码标价招募（名声/恶名双轨门槛）+ 赠礼交好（美酒 +30 好感）
- ✅ **市场**：买卖粮/木/铁（含城池等级物价系数）+ 买卖消耗品
- ✅ **铁匠铺**：9 件装备按城池等级 + 区域解锁（藤甲护甲限南中）
- ✅ **官府内政**：开仓施赈（金→民心）、修缮城防（木+金→城防）
- ✅ **民心 = 征兵的核心约束**（M5 最重要的数值决策）
  —— 每 10 兵扣 2 民心。建宁单次最多征 200 兵（民心上限），而每日名额是 300 兵。
  **大城先撞"民心墙"、中城先撞"名额墙"**，两种约束互补，内政终于有了存在感。
  民心触底（≤30）后征兵通道**自动关闭**，形成天然的扩军节奏。
- ✅ **战役演练模式**（原版没有的原创补充）★★
  —— 官府 → 演武场 → 6 套假想敌预设 → 自由布阵试演。
  `GameState.drill_mode` 单布尔量贯穿三场景。**不消耗兵力、不掉兵、无奖励、不写存档**。
  理由：原版战斗全靠实战，一吃败仗就掉兵，玩家不敢试新配兵 ——
  这恰恰扼杀了 M3/M4 设计的阵型与克制系统的价值。
- ✅ **统兵加成链路打通**：`GameState.troops[i].hero_id` → `FormationCalculator` → 战力倍率
  （M3 时期这条链路是断的，M5 补齐）
- ✅ **背包系统**：`GameState.inventory` + `equipment`，已并入存档序列化
- ✅ 新增 4 张数据表：`barracks.json` / `recruit_pool.json` / `shop_goods.json` / `drill.json`

> ⚠️ 当前所有可视元素默认用**程序化绘制**占位（已具备地貌层次感）。
> 把美术资源按 `03-美术资源/08-M2资源映射表.md` 放入对应目录后，**无需改代码**即自动切换为贴图渲染。
> 美术风格参考：`03-美术资源/样图/`（已生成的 4 张二次元国风样图）。

## 二、如何运行

### 2.1 用 Godot 打开

1. 启动 **Godot 4.x**（标准版即可）
2. 点「导入」→ 选择本目录下的 `project.godot`
3. 点「导入并编辑」
4. 按 **F5** 运行（首次会提示选择主场景，选 `boot.tscn`）

### 2.1.1 如果 F5 报错跑不起来 —— 先做这两件事

**第一步：跑工程自检。** 在 `04-Demo/` 目录下执行：

```
python _run_all_checks.py
```

7 个校验脚本会一次性跑完（JSON 合法性 / 资源引用 / 节点数 / 类型推断 / 原生类撞名 /
**Godot 实际编译** / 各系统数值），哪一项不通过会直接打印出来。

**第二步：核对最常见的报错类型。**

| 报错 | 原因 | 修法 |
| --- | --- | --- |
| `Cannot infer the type of "x" variable because the value doesn't have a set type` | 用 `var x := ...` 推断类型，但右侧表达式的类型不确定 | 改成**显式类型**：`var x: float = ...` |
| `The variable type is being inferred from a Variant value` (Warning treated as error) | 同上，右侧是 `.get()` / 字典下标取值（Variant） | 加显式类型或 `float()` / `str()` 包裹 |
| `Class "X" hides a native class` | 自定义 `class_name` 与 Godot 内置类**撞名** | 改名（本项目 `VirtualJoystick` → **`GameJoystick`**） |
| `Identifier "X" not declared in the current scope` | `%X` 引用的节点在 `.tscn` 里没加 `unique_name_in_owner = true` | 在场景文件对应节点下补这一行 |
| 点击按钮没反应 / 界面错位 | 场景节点结构被改动，脚本里的 `$Path` 失效 | 跑 `_validate.py` 看节点一致性 |

> **类型推断与类名撞名是 GDScript 最常见的"一运行就崩"两兄弟。**
> 记住两条规律：
> 1. **右侧出现"来源没有明确类型"的变量**（无类型数组的循环变量、`.get()` 取值、
>    未标注类型的函数参数）→ 不要用 `:=`，直接写 `var x: String = ...`。
> 2. **自定义 `class_name` 前先确认不是引擎内置类名**
>    （Godot 4.7 起内置了 `VirtualJoystick`！）→ `_validate.py` 会对照
>    `_godot_native/native_classes.json`（1054 个原生类名）自动检查。
>
> **本项目已遇到并修复的实例**（供参考，说明这类问题有多隐蔽）：
> - `VirtualJoystick` 撞 Godot 4.7 原生类 → 改名 `GameJoystick`
> - `var path := PLAYER_TEX_DIR + name_candidate + ext` → 无类型循环变量参与拼接
> - `var g2 := g`（`g` 来自无类型数组）→ 改 `var g2: Dictionary = g`
> - `targets[i].hp`（`targets` 是无类型 Array）→ 把 `_live()` 改为返回 `Array[BattleUnit]`
> - `rm["bonus"]`（字典下标是 Variant）→ 改 `float(rm["bonus"])`

### 2.1.2 为什么 `_compile_check.py` 最重要

`_validate.py` 用正则做静态扫描，**会漏检**（本项目实测：正则方案漏掉了 9 处真实错误）。

`_compile_check.py` 则**直接调用 Godot 编译全部 25 个脚本**，报的是引擎的真实判断，
不靠猜。它会自动过滤掉 `--script` 模式下因 autoload 未加载而产生的
`Identifier not found: GameState` 等**假错误**。

> 单独运行方式：
> ```
> python _compile_check.py
> ```
> 若 Godot 不在默认路径，修改脚本顶部的 `GODOT_CANDIDATES`。

> **这套排错方法论已固化为通用技能**，以后遇到任何 Godot 工程报错，
> 可直接加载用户级 Skill **`godot-project-healthcheck`** 使用：
> - `scripts/compile_check.py` —— 真实编译全部脚本（等价本项目 `_compile_check.py`，支持 `--project` 参数）
> - `scripts/smoke_test.py` —— 无头启动冒烟测试（抓 `_ready` / autoload / 数据表问题）
> - `scripts/scene_check.py` —— 场景 `load()` + `instantiate()` 检查（抓"点进某界面才崩"的问题）
> - `references/gdscript-pitfalls.md` —— GDScript 类型系统坑位详解与完整错误对照表
>
> 技能路径：`~/.workbuddy/skills/godot-project-healthcheck/`

### 2.2 操作方式

| 场景 | 操作 |
| --- | --- |
| 主菜单 | 鼠标 / 触屏点按钮。「继续游戏」在没有存档时置灰 |
| 大地图 | 左下摇杆移动（桌面用鼠标拖拽模拟）；靠近城池后「进入」键亮起 |

| **城池（M5）** | 点建筑卡片打开抽屉面板；面板内操作原地刷新（连点 10 次征兵不用重复开面板）；「关闭」或安卓返回键关面板；底部「离开」返回大地图 |
| **演武场（M5）** | 官府 →「进入演武场」→ 选假想敌 → 布阵界面按钮变「试 演」→ 战场不消耗兵力 |

> 完整战斗流程：大地图踩到战斗图标 → **战前布阵界面**（选阵型 / 摆阵位 / 看胜率）→ 开战 →
> **即时战场**（部队自动交战，玩家操作主角 + 下达全军指令）→ 战后结算返回大地图。
>
> 完整经营流程：大地图进入城池 → **五建筑界面** → 酒馆招募武将 / 兵营征兵练兵 /
> 市场补充物资 → 官府查看民心 → 演武场试摆 → 离开 → 踩战斗图标 → 布阵 → 出战。

### 世界层脚本（M2 核心）

## 七、战前布阵系统说明（M3）

详细设计见 `02-策划文档/10-阵型编辑器设计.md`。核心要点：

### 7.1 3×5 阵位网格

```
        列1    列2    列3    列4    列5
      ┌──────┬──────┬──────┬──────┬──────┐
前军  │ 左锋 │ 左翼 │ 中锋 │ 右翼 │ 右锋 │   ← 攻击高、防御低
      ├──────┼──────┼──────┼──────┼──────┤
中军  │ 左卫 │ 左辅 │ 中坚 │ 右辅 │ 右卫 │   ← 攻守均衡
      ├──────┼──────┼──────┼──────┼──────┤
后军  │ 左辎 │ 左帐 │ 中帐 │ 右帐 │ 右辎 │   ← 防御高、攻击低
      └──────┴──────┴──────┴──────┴──────┘
```

### 7.2 行-兵种协同

| 行 | 适配 | 加成 | 冲突 |
| --- | --- | --- | --- |
| 前军 | 步兵 | 防御 +10% | 弓兵 → 攻击 −25% |
| 中军 | 骑兵 / 精英 | 攻击 +8% | 无 |
| 后军 | 弓兵 | 攻击 +15% | 骑兵 → 战力 −20% |

### 7.3 战力公式

```
单支部队战力 = 兵力 × (1+阵型攻击) × (1+阵位攻击) × (1+行协同) × 兵种品质 × 武将加成
总战力       = Σ 各部队战力
胜率         = Logistic(1.1 × ln(我方总战力 / 敌方总战力))
```

### 7.4 验证结论（`_verify_formation.py` 交叉验证）

| 测试 | 结果 |
| --- | --- |
| 自动布阵 | 步兵自动占中锋，弓兵自动进后军，符合设计 |
| 位置差异 | 同一弓兵：前军中锋 175 战力 vs 后军中帐 229 战力，差 **31%** |
| 阵型差异 | 同一布阵六阵型战力 1054~1464，锋矢阵最高（攻击加成最大） |
| 胜率曲线 | 战力比 1:1 → 50%，2:1 → 68%，3:1 → 77%，曲线平滑合理 |
| 武将加成 | 诸葛亮（统率96）中帐位 ×1.46，吕布（统率56）×1.06，差异显著 |

## 七·B、部队 AI 自动交战说明（M4）★★

详细设计见 `02-策划文档/11-部队AI自动交战设计.md`。核心要点：

### 7B.1 战斗架构

```
BattleScene（输入输出 / HUD / 结算）
    └─ BattleDirector（总指挥：布置部队 / 驱动 tick / 判胜负）
            └─ BattleUnit × N（单支部队：状态机 / 索敌 / 攻防 / 士气）
```

**战斗逻辑与渲染完全解耦** —— `BattleDirector` 只操作坐标与数值，
`BattleUnit` 自己负责绘制。贴图就绪后只需替换 `_build_visual()`，战斗逻辑一行不改。

### 7B.2 双轨生命值

| 轨道 | 受击变化 | 作用 |
| --- | --- | --- |
| `hp` 血量 | `− 伤害值` | 由兵种决定承受力 |
| `count` 兵力 | `− ceil(伤害 × 0.55)` | 人数，直接影响输出 |

**兵力系数**（残兵越少输出越低）：

```
兵力系数 = clamp(残兵 / max(30, 初始兵力) × 0.7 + 0.3, 0.3, 1.0)
```

> 这让"打残"比"打死"更有战术价值——残兵部队输出暴跌，可以先放着不管。

### 7B.3 士气三源压力模型（关键设计）

```
士气衰减 = (伤害压力 + 兵力压力 + 持续压力) × morale_decay_per_loss × 0.5

伤害压力 = (本次伤害 / 最大血量) × 100 × 0.45    ← 打不过
兵力压力 = (1 − 残兵比)          × 100 × 0.22    ← 快死光了
持续压力 = 3.2（每次受击固定）                    ← 防僵持局
```

> **踩过的坑**：士气公式初版写成 `伤害 × 0.12 × 1.6 × 0.1`，
> 打 28 点伤害只掉 0.54 士气，导致**所有部队都是被打死、从没触发过溃散**，
> 「固守 +35%」「大招 +15 士气」全部失去意义。三源模型修复了这个问题。

**溃散判定先于阵亡判定** —— 兵败如山倒：人还在，但仗已经不想打了。

### 7B.4 伤害公式

```
单次伤害 = 攻击力 × 兵力系数 × (1 + 布阵加成 + 冲锋 + 固守惩罚)
           × 克制倍率 × 0.085 × 10 × 防御减伤 × (1 ± 25% 随机)
末值 = max(1.0, 结果)
```

| 因子 | 取值 |
| --- | --- |
| 克制倍率 | 1.25 克 / 0.80 被克 |
| 冲锋加成 | +55%，持续 2.2 秒，移速 ×1.6 |
| 固守 | 攻 −20% / 受击 −35% |
| 防御减伤 | `clamp(1 − 防御×加成/120, 0.35, 1.0)`，保底 35% |
| 随机浮动 | ±25%（让"以弱胜强"成为可能） |

### 7B.5 索敌评分（AI 性格）

```
目标评分 = 距离 × 1.2 + 克制 × 0.55 + 残血 × 0.45 + 兵种偏好 × 0.3
```

读出来的 AI 行为：
- **优先切弓兵**（target_priority 1.35）——弓兵输出高又脆
- **顺手收残血**（权重 0.45）——不会傻乎乎一直打满血前排
- **主动找克制目标**（权重 0.55）——枪兵会绕开弓兵去找骑兵
- 象兵 / 精英排最后打（0.85 / 0.95）——AI 知道"啃硬骨头要挑时机"

### 7B.6 固定步长 tick

```
每帧累加 delta，每满 0.25 秒执行一次 _simulate()
```

> **为什么不用帧 delta**：高端机 120fps、低端机 30fps，如果用帧 delta，
> 高帧率设备的部队会因累积误差而攻击频率更高。
> 固定步长保证**同样配置在任何设备打出同样结果**，也与 M3 的胜率预估口径一致。

### 7B.7 验证结论（`_verify_combat.py` 交叉验证，13 项全通过）

| 测试 | 结果 |
| --- | --- |
| 兵种克制 | 枪兵打骑 **21.4** vs 打弓 **14.2**，比值 **1.51** |
| 冲锋加成 | 普通 28.3 → 冲锋 43.8（**×1.55**） |
| 固守减伤 | 守方固守受击 14.9 → 9.7（**免伤 35%**） |
| 重甲溃散 | 藤甲兵第 8 次受击后溃散，**残兵 88/160**（兵败而非兵亡） |
| 轻甲战死 | 弓箭手第 3 次受击就阵亡（脆皮来不及崩溃） |
| 完整战斗 | 3v3 约 45 tick（≈11 秒）正常分胜负，不死循环 |
| 兵力优势 | 3 倍兵力方稳定获胜 |
| 主力介入 | 大招把战斗从 48 tick 压到 36 tick，并大幅鼓舞士气 |

## 七·C、城池经营与招募说明（M5）★★★

详细设计见 `02-策划文档/12-城池经营与招募系统设计.md`。核心要点：

### 7C.1 架构：为什么要抽一个 CityService

M2 的 `city_scene.gd` 只有 68 行，是个占位脚本。如果 M5 直接在 UI 里写判定，会出现三个问题：

1. **测不了** —— 判据埋在按钮回调里，Python 无法独立复核
2. **改不动** —— 调一个数值要翻遍所有回调
3. **会漂移** —— 兵营和官府对"民心"的理解可能不一致

所以 M5 建立了 `CityService`：

```
显示层  city_scene.gd     建按钮 / 填文本 / 弹提示       ← 禁止写数值公式
规则层  city_service.gd   全部判定与结算                 ← 禁止引用场景节点
数据层  assets/data/*.json 全部可调数值                  ← 禁止被硬编码覆盖
状态层  game_state.gd     存档数据 + 变更广播            ← 禁止做业务判定
```

UI 里只写一行：

```gdscript
var r := _svc.recruit(city_id, unit_id, 10)
show_toast(r["msg"])   # ← 就这么简单
```

**回报**：规则层可以被 Python 完整重新实现一遍并逐个比对 ——
`_verify_economy.py` 就是这样做的，一次就抓出了民心公式的设计缺陷。

### 7C.2 民心：Demo 阶段真正的瓶颈（M5 最重要的数值决策）

**问题**：初版公式 `ceil(count / 50)` 扣民心。建宁民心 70、下限 30 →
民心能支撑 `40 × 50 = 2000` 兵，而每日名额上限才 300 兵。
**结果：民心约束形同虚设**，玩家只会撞到"名额墙"，永远感受不到内政的存在。

**修正**：改为按批次扣，每 10 兵扣 3 民心。

```
民心消耗     = ceil(征募人数 / 10) × 3
民心可征容量 = floor((当前民心 − 下限30) / 2) × 10
实际可征上限 = min(每日名额, 民心可征容量)
```

**实测（`morale_cost_per_batch = 2`）**：

| 城池 | 民心 | 民心上限 | 每日名额 | 实际可征 | 卡在哪 |
| --- | --- | --- | --- | --- | --- |
| 建宁 | 70 | **200 人** | 300 人 | 200 人 | 民心 |
| 云南 | 72 | 210 人 | 180 人 | 180 人 | 名额 |
| 滇池城 | 68 | 190 人 | 160 人 | 160 人 | 名额 |
| 牂牁 | 70 | 200 人 | 170 人 | 170 人 | 名额 |
| 永昌 | 65 | 170 人 | 200 人 | 170 人 | 民心 |
| **五城合计** | — | — | — | **880 人** | — |

**880 人**够打 3~6 场 3v3（每场 300~600 兵）。既不会"兵多得用不完"，也不会卡到打不动。

> 调参记录：初版 3 点/10 兵 → 建宁上限 130，民心卡得太死，玩家扩张受限明显。
> 现调为 **2 点/10 兵 → 建宁 200**，与每日名额 300 形成"一紧一松"的互补
> （大城卡民心、中城卡名额），节奏更顺。

民心触底（≤30）后征兵通道**自动关闭**，形成天然节奏：

```
征兵 → 民心下降 → 触底 → 施赈或等日推 → 恢复 → 继续扩军
```

施赈 `-金 200 → 民心 +5`（约 25 兵额度），明显贵于直接征兵（25 兵仅 100 金）
—— **施赈是应急手段，不是可循环的刷兵途径**。

> **UI 上把瓶颈显式写出来**是 M5 手感的关键。兵营面板会直接显示：
> `※ 当前受【民心】限制，实际还可征 200 人。施赈（官府）可恢复民心。`
> 玩家不需要自己算，界面直接告诉他"卡在哪、该去做什么"。

### 7C.3 征兵成本曲线

| 兵种 | 10 兵金 | 10 兵粮 | 100 兵金 | 100 兵粮 | 定位 |
| --- | --- | --- | --- | --- | --- |
| 刀盾兵 | 40 | 20 | 400 | 200 | 基础抗线 |
| 长枪兵 | 50 | 25 | 500 | 250 | 克骑克象 |
| 弓箭手 | 60 | 25 | 600 | 250 | 远程（需 2 级城） |
| 轻骑兵 | 80 | 40 | 800 | 400 | 机动突击（需 2 级城） |
| 藤甲兵 | 70 | 30 | 700 | 300 | 南中特产，防高惧火 |
| 象兵 | **220** | **90** | 2200 | 900 | 王牌，需 3 级城 + 民心 ≥60 |

- 成本与人数**严格线性**
- 藤甲兵溢价 **1.75×**（合理区间 1.5~2.0）—— 对应它 45 的防御（刀盾兵仅 15）
- 象兵为最贵兵种 —— 对应它 320 血 / 45 攻 / 30 防的全场最强面板

### 7C.4 兵种解锁的四重门禁

```
1. unlock_city_level   城池等级
2. buildings 含 barracks          ← 无兵营则不产出
3. require_region / require_faction / require_specialty   ← 区域 / 势力 / 特产
4. require_morale      民心门槛（象兵需 ≥60）
```

**设计效果**：14 个兵种在 Demo 里**不可能全部入手**。
龙枪兵/虎豹骑/白马义从/羌弓骑 会显示「需 shu 势力城池」这样的灰字提示
—— **让玩家看见"未来还有更多"**，这是长期养成动机的来源。

### 7C.5 练兵：一条经济替代路径

```
练兵成本：粮 8 / 10 兵（得经验 8）
升级阈值：100 经验 → 需练 13 次 → 累计耗粮 104
```

**对比**：征 100 兵要 200 粮，练兵升一级只要 104 粮（约一半）。
**练兵比"重新征兵"更便宜**，但要付出 13 次点击的时间成本 ——
这是刻意给耐心型玩家留的一条不靠砸钱的路径。溢出经验正确结转（不丢失）。

> 调参记录：初版 `train_exp_per_10 = 5` → 需练 20 次，节奏偏慢。
> 现调为 **8 → 需练 13 次**，配合民心放宽（200 人）后整体扩张节奏明显更顺。

**统兵加成**：

```
统率 = (智力 + 魅力) / 2
加成倍率 = clamp(0.6 + 统率/100, 0.6, 1.6)
```

| 武将 | 统率 | 倍率 |
| --- | --- | --- |
| 诸葛亮 | 96 | **×1.56** |

> 吕布的强大应体现在**个人战**（主角单挑 / 武将技），
> 而统兵加成衡量的是**指挥能力**。
> 诸葛亮 ×1.56 配合中帐位的翻倍（M3 已验证：中帐加成 ×2），

### 7C.7 战役演练模式（M5 原创补充）

**为什么做**：原版战斗全靠实战，玩家一吃败仗就掉兵，导致不敢尝试新配兵 ——
这恰恰扼杀了 M3/M4 设计的阵型与克制系统的价值。
演练把"学习成本"从"掉兵的代价"里剥离出来。

**实现**：`GameState.drill_mode` 一个布尔量贯穿三场景。

```
城池官府「进入演武场」
   ↓ _svc.drill_as_encounter(drill_id)   把演练预设转成 encounter 结构
   ↓ GameState.drill_mode = true
   ↓ SceneRouter.push_scene("formation")
布阵界面
   ↓ 识别 drill_mode → 标题「演武 · 敌情：xxx」
   ↓ 按钮文案改为「试  演」/「退出演武」
   ↓ _on_fight() 跳过 formation_slots 写回 + SaveManager.auto_save()
战场
   ↓ 识别 drill_mode → 走 _on_drill_finished() 专属结算
   ↓ 不调 _apply_defeat_penalty()（失败不掉兵）
   ↓ 不发奖励、不自动存档
   ↓ 显示「推演结果：胜/败 …… （演武不消耗兵力，无奖励）」
「确认」→ SceneRouter.back() → 回到布阵界面，可继续试摆
```

**6 套假想敌预设**（`drill.json`）：

| ID | 名称 | 难度 | 构成 | 教学意图 |
| --- | --- | --- | --- | --- |
| `drill_militia` | 乡勇试阵 | ★ | 刀盾兵×100 | 入门：熟悉网格与阵型 |
| `drill_bandit_group` | 山贼来袭 | ★★ | 刀盾兵×150、弓箭手×80 | 体验远近配合 |
| `drill_cavalry_raid` | 骑兵突袭 | ★★★ | 轻骑兵×200 | 教"长枪兵克骑兵" |
| `drill_rattan_line` | 藤甲铁壁 | ★★★★ | 藤甲兵×200 | 教"高防单位会溃散而非战死" |
| `drill_elephant_corps` | 象阵冲锋 | ★★★★ | 象兵×60、藤甲兵×150 | 教"枪兵+集火" |
| `drill_elite_guard` | 精锐亲卫 | ★★★★★ | 虎豹骑×80、连弩兵×150 | 终局检验 |

**三条硬约束**（已由 `_check_m5.py` 自动校验）：

1. 不写 `GameState.formation_slots`、不调 `SaveManager.auto_save()`
2. 不调 `_apply_defeat_penalty()` —— 失败不掉兵
3. 不发奖励、不涨名声 —— 不是刷资源漏洞

## 九、开发提示

- **改数据不用重启**：Godot 里改 JSON 后重新运行即可（`DataManager._ready()` 会重新加载）
- **一键全量校验**：`python _run_all_checks.py` —— 一次跑完 6 个脚本并汇总
- **工程自检**：`python _validate.py` 校验 JSON 合法性、资源引用、class_name 重复、场景节点数、
  **GDScript 类型推断风险**、缩进规范、**原生类撞名**
- **★ 实际编译**：`python _compile_check.py` 让 Godot 真实编译全部脚本 ——
  **最可靠的检查**，正则扫描会漏，引擎编译不会
- **一键全跑**：`python _run_all_checks.py`（7 个校验脚本依次执行并汇总结果）
- **公式验证**：`python _verify_formation.py` 独立复算阵型战力公式
- **战斗结构**：`python _check_m4.py` 校验战场节点路径与 combat.json 配置一致性
- **战斗数值**：`python _verify_combat.py` 独立复算 M4 战斗系统（13 项，含完整战斗模拟）
- **城池结构**：`python _check_m5.py` 校验 M5 场景节点 / 数据表 / 方法 / 演练闭环 / 交叉引用
- **经济数值**：`python _verify_economy.py` 独立复算 M5 经济与招募（29 项）
- **调阵位数值**：直接改 `assets/data/formation_slots.json`，不用碰代码
- **调战斗平衡**：直接改 `assets/data/combat.json`，不用碰代码
  （克制倍率 / 冲锋加成 / 士气衰减 / 索敌权重 全在这里）
- **调经济数值**：改 `barracks.json`（征兵成本/民心消耗/练兵）、`shop_goods.json`（物价/回收比）、
  `recruit_pool.json`（武将定价/名声门槛）、`drill.json`（演武预设），**全部不用碰代码**
- **改民心强度**：`barracks.json` 的 `morale_cost_per_batch`（当前 2）
  —— 调到 2 则建宁单次可征 195 兵（手感更松）
- **改练兵节奏**：`barracks.json` 的 `train_exp_per_10`（当前 8，13 次升一级）
  —— 调到 8 则 13 次升一级（不那么肝）
- **调试存档**：存档在 `user://saves/`，Windows 下位于
  `%APPDATA%\Godot\app_userdata\纪元三国\saves\`
- **手机触控**：`VirtualJoystick` 已同时支持 `InputEventScreenTouch` 和鼠标事件，桌面可直接调试
- **性能**：`project.godot` 已锁定 Compatibility 渲染器 + `Engine.max_fps` 建议设为 60
- **特效注意**：Compatibility 渲染器下 GPUParticles 会静默失效，请用 **CPUParticles2D**
- **程序化绘制开销**：`TerrainPainter` 每帧重绘装饰物，若帧率不足可降低 `DECOR_COUNT`
- **对象型配置表**：`formation_slots.json` / `combat.json` / `barracks.json` / `recruit_pool.json`
  / `shop_goods.json` / `drill.json` 是**对象**（非数组），`DataManager` 会包成单条记录并赋予
  `id="root"`，用 `get_record("barracks", "root")` 读取（已有便捷接口 `get_barracks_settings()` 等）
- **战斗调参入口**：所有战斗数值都在 `combat.json`，脚本内**禁止硬编码** ——
  这样调平衡不用改代码，也能保证 Python 复核脚本与 GDScript 实现始终一致
- **经济调参入口**：所有经营数值都在上述 4 张 M5 数据表，`city_service.gd` 内**禁止硬编码** ——
  同理，这是 `_verify_economy.py` 能作为独立复核基准的前提
- **新增兵种时要同步 3 处**：`units.json` 加兵种 → `combat.json` 的 `counter_matrix` 加克制关系
  → 可选地在 `target_priority` 里加类别权重
- **新增可征兵种时要第 4 处**：`barracks.json` 的 `units` 数组加征兵配置
  （否则兵种存在但永远无法征募）；`_check_m5.py` 的交叉一致性检查会抓出遗漏
- **UI 层纪律**：`city_scene.gd` 里**不允许出现数值公式**。
  如果发现需要算东西，那说明该逻辑应该加进 `CityService` ——
  这样它才能被 `_verify_economy.py` 复核到
